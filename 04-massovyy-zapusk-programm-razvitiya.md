# Массовый запуск программ развития

Корпоративный университет позволяет запускать программы развития (ИПР) для сотрудников как индивидуально, так и массово. Индивидуальный (одиночный) запуск выполняется через профиль конкретного пользователя. Массовый запуск выполняется через раздел Корпоративного университета «Сотрудники». 

В этой статье рассмотрены все варианты массового запуска программ развития. Об одиночном запуске программ развития написано [здесь](../../../../modules/ithive.ipr/user-guide/06-razvitie-sotrudnikov/03-odinochnyy-zapusk-programm-razvitiya.md).

## Права на массовый запуск программ развития

В Корпоративном университете есть 2 роли пользователей, которым доступен массовый запуск программ развития:

- Администратор

- [Группа HR-отдела](../../../../modules/ithive.ipr/user-guide/09-administrativnaya-chast-modulya/03-nastroyki-modulya-korporativnyy-universitet.md)

Обратите внимание, что у обычных сотрудников и структурных руководителей есть права только на одиночный запуск развития. Доступа к массовому запуску у таких пользователей нет.

## Варианты массового запуска развития

Всего в модуле предусмотрено 3 варианта запуска программ развития:

1. **Запуск по шаблону программы развития/адаптации.** Доступен для массового и одиночного запуска.

2. **Запуск со свободным выбором компетенций.** Доступен для массового и одиночного запуска.

3. **Запуск на основе карьерной траектории/текущей позиции.** Недоступен для массового запуска, может использоваться только при одиночном запуске.

Массовый запуск означает, что для выбранного количества сотрудников будет запущена одна и та же выбранная программа развития. При массовом запуске невозможно выбрать для каждого сотрудника свою программу развития.

### Запуск по шаблону программы развития/адаптации

В этом случае при запуске программы развития нужно выбрать соответствующий шаблон. Шаблон — это заранее подготовленный набор компетенций для освоения. При создании шаблона HR-специалист самостоятельно решает, какие компетенции в него включить. Запущенная программа развития будет содержать указанные компетенции.

Например, в шаблон «Онбординг нового сотрудника» могут входить такие компетенции как «Знание продуктовой линейки», «Знание основной информации о компании» и тому подобное. О нюансах выбора компетенций для развития написано ниже.

Шаблоны можно создавать как для обычных программ развития, так и для программ адаптации. Опции запуска развития по шаблону выглядят следующим образом:

![](./_images-04/image352.png)

### Запуск со свободным выбором компетенций

В этом случае при запуске развития не нужно выбирать шаблон. HR-специалист сам выбирает компетенции, которые нужно развить, прямо в процессе запуска. Такой вариант запуска используется для целенаправленной отработки отдельных компетенций.

## Массовый запуск программ развития

Рассмотрим особенности запуска каждого из двух вариантов развития. Запуск развития выполняется из раздела «Сотрудники». Для этого отметьте нужных сотрудников галочками в списке и выберите действие «Запустить программу». После этого выберите нужный вариант запуска программы развития.

![](./_images-04/image689.png)

### Программа адаптации/развития по шаблону

При выборе такого варианта запуска на слайдере будут доступны следующие поля:

1. **Выберите шаблон**. Опция появляется только если при запуске была выбрана опция «Программа адаптации по шаблону»/«Программа развития по шаблону». В поле нужно выбрать шаблон программы развития или адаптации. Компетенции из шаблона будут автоматически выбраны в блоке справа — их можно оставить без изменений или отредактировать под конкретного сотрудника.

[Создание шаблона программ](../../../../modules/ithive.ipr/user-guide/06-razvitie-sotrudnikov/05-sozdanie-shablona-programm.md)

![](./_images-04/image269.png)

2. **Как определять руководителя.** Поле для выбора руководителя, который будет следить за выполнением программы развития. От руководителя зависят оценки по компетенциям и завершение развития. Поле обязательно для заполнения.

При массовом запуске есть два варианта выбора руководителя:

- **Вычислить руководителя по организационной структуре.** В этом случае для каждого выбранного сотрудника будет автоматически указан руководитель согласно организационной структуре. Если определить руководителя невозможно, то на следующем шаге его нужно будет указать вручную.

![](./_images-04/image56.png)

- **Выбрать одного руководителя на весь запуск.** В этом случае нужно выбрать одного пользователя, который станет руководителем во всех запускаемых карточках развития. При необходимости на следующем шаге можно будет выбрать руководителя индивидуально для каждого сотрудника.

3. **Отправить на согласование руководителю**. Если галочка включена, то после запуска карточка будет находиться в статусе «Черновик» пока ее не одобрит указанный руководитель. Если опция отключена, то при запуске программа сразу попадет сотруднику в работу.

4. **Наблюдатели.** В данном поле можно указать пользователей, которым карточка развития будет доступна для просмотра в разделе «Мониторинг развития». Также во всех разделах аналитики по курсам наблюдатели видят результаты тестирования сотрудника по тем курсам, которые добавлены в данную карточку развития.

![](./_images-04/image472.png)

5. **Срок.** Длительность выполнения программы развития. В это поле автоматически проставляется срок из выбранного шаблона программы, однако его можно изменить. Для программы онбординга этот срок может быть от 1 до 3 месяцев, для программы развития — от 6 месяцев и до 2 лет. Добавить новые сроки можно в [административной части] портала.

6. **Указать/Скрыть целевую должность.** Если должность указана, то у руководителя карточки будет возможность автоматически установить эту должность в профиле сотрудника после завершения развития. Если не этого делать нужно, данное поле можно не заполнять. Поле будет автоматически заполнено если в выбранном шаблоне развития указана целевая должность.

![](./_images-04/image711.png)

7. **Указать/Скрыть целевую позицию**. Если позиция указана, то у руководителя карточки будет возможность автоматически установить эту позицию в профиле сотрудника после завершения развития. Если не этого делать нужно, данное поле можно не заполнять. Поле будет автоматически заполнено если в выбранном шаблоне развития указана целевая позиция.

[Схема карьерных траекторий](../../../../modules/ithive.ipr/user-guide/04-karernye-traektorii-i-pozitsii/02-shema-karernyh-traektoriy.md)

![](./_images-04/image708.png)

8. **Указать/Скрыть следующую программу.** Опция нужна для автоматизации запуска программ развития и позволяет сотрудникам после завершения одной программы приступать к выполнению следующей. Данная опция может быть использована, например, для выстраивания аналога карьерной траектории. Если не нужно, чтобы сотрудник приступал к выполнению следующей программы развития, данное поле можно не заполнять.

![](./_images-04/image193.png)

9. **Компетенции.** В этом блоке происходит выбор компетенций для развития. При указании шаблона компетенции из него автоматически отмечаются галочками, т.е. становятся выбраны для развития. Автоматически выбранные компетенции нельзя удалить.

    Обратите внимание, что в отличие от одиночного запуска здесь напротив компетенций не выводятся уровни владения. Увидеть компетенции, которыми уже владеет сотрудник, и убрать их из запускаемой программы можно будет на [следующем шаге](#nastrojka-i-proverka-dannyh-pered-zapuskom).

![](./_images-04/image628.png)

Помимо автоматически добавленных компетенций для развития можно выбрать и любые другие существующие компетенции.

Для каждой компетенции можно указать свой срок развития, а также набор развивающих действий. Подробнее об этом написано [следующем шаге](#nastrojka-i-proverka-dannyh-pered-zapuskom).

## Сроки развития компетенций и развивающие действия

Для каждой компетенции доступен выбор даты дедлайна. По умолчанию указан дедлайн самого позднего развивающего действия по данной компетенции. Если указать крайний срок выполнения вручную, то эта дата будет автоматически выставлена для всех развивающих действий по данной компетенции.

В дальнейшем сроки выполнения развивающих действий можно будет настроить вручную в самой карточке развития. Для этого у пользователя должны быть соответствующие [права доступа](../../../../modules/ithive.ipr/user-guide/09-administrativnaya-chast-modulya/03-nastroyki-modulya-korporativnyy-universitet.md).

![](./_images-04/image169.png)

По клику на кнопку «Действий N/M» откроется слайдер выбора развивающих действий для данной компетенции. Выбранные действия будут включены в программу развития. M — это количество обязательных развивающих действий для данной компетенции. N — это количество действий из числа M, которые выбраны для прохождения.

![](./_images-04/image756.png)

На слайдере выбора развивающих действий вы можете отредактировать цель развития, выбрать/убрать развивающие действия из программы и указать дедлайны для развивающих действий.

![](./_images-04/image577.png)

Ниже на слайдере расположена кнопка «Добавить» по клику на которую в программу развития можно добавить любые другие виды развивающих действий.

![](./_images-04/image83.png)

Обратите внимание, что для добавления доступны только уже созданные действия. Данный интерфейс не предусматривает создание новых развивающих действий.

После заполнения основных полей нажмите «Далее» на слайдере запуска развития. В результате вы перейдете на второй и последний шаг массового запуска карточек развития.

![](./_images-04/image683.png)

## Настройка и проверка данных перед запуском

На втором шаге можно изменить руководителей карточек для сотрудников, убрать из развития уже освоенные компетенции и отменить запуск для отдельных сотрудников. Данный шаг идентичен для всех вариантов запуска. Рассмотрим слайдер подробнее.

### Фильтры по запускаемым карточкам

В верхней части слайдера находятся четыре фильтра:

1. **Исходное выбранное количество сотрудников.** Данный фильтр выбран по умолчанию. Когда выбран этот фильтр, на слайдере выводится полный список всех сотрудников, которые были выбраны для запуска развития.

2. **Сотрудники с имеющимися компетенциями.** По клику на фильтр на слайдере выводятся только те сотрудники, которые уже владеют какими-то из компетенций, выбранных для развития (![](./_images-04/image246.png) и
    ![](./_images-04/image613.png)).

3. **Будет запущено.** По клику на фильтр на слайдере выводятся только те сотрудники, для которых карточки развития будут успешно запущены, т.е. нет препятствующих этому факторов.

![](./_images-04/image491.png)

4. **Не будет запущено.** По клику на фильтр на слайдере выводятся только те сотрудники, для которых карточки развития НЕ будут запущены. О причинах, блокирующих запуск, написано в колонке «Комментарий». Есть 4 причины, которые блокируют запуск развития:

- В данный момент у сотрудника в работе уже есть программа развития, запущенная по такому же шаблону.

- Превышен лимит на количество программ, которые могут одновременно находиться у сотрудника в работе. По умолчанию лимит — 2 программы, но в настройках модуля его можно увеличить до 5-ти.

- Сотрудник уволен. Для уволенных сотрудников запуск карточек развития невозможен.

- Для сотрудника вручную отменен запуск развития. Если в колонке «Сотрудник» снять галочку напротив нужного пользователя, то программа развития для него не будет запущена.

### Таблица со списком сотрудников

Далее на слайдере располагается таблица для проверки данных и финальной настройки карточек перед запуском. Здесь доступны следующие колонки:

1. **Сотрудник.** Здесь выводится профиль сотрудника, для которого нужно запустить развитие. Слева от ФИО сотрудника находится чекбокс: если галочка активна, программа развития для этого сотрудника будет запущена. Если галочку снять, программа для этого сотрудника не будет запущена.

    Если галочка снята, а сам чекбокс заблокирован — значит есть факторы блокирующие запуск развития для этого сотрудника и карточка не будет запущена. Причина, блокирующая запуск, указана в колонке «Комментарий».

![](./_images-04/image63.png)

2. **Руководитель.** В данном поле выводится руководитель программы развития, указанный ранее на первом шаге. При необходимости руководителя можно изменить. Поле может быть пустым, если на первом шаге было решено определять руководителя на основе оргструктуры, но согласно структуре у сотрудника нет руководителя. В этом случае руководителя нужно будет указать вручную.

![](./_images-04/image601.png)

3. **Имеющиеся компетенции.** Здесь выводятся те из развиваемых компетенций, которыми сотрудник уже владеет на достаточном или экспертном уровне (![](./_images-04/image246-2.png) или ![](./_images-04/image613-2.png)). Напротив компетенций будет показан текущий уровень владения ими у сотрудника. С учетом этой информации HR-специалист может решить, нужно ли сотруднику дальше развивать уже имеющиеся компетенции или нет.

    Рядом с компетенциями доступен чекбокс: если галочка активна, компетенция будет добавлена в карточку развития. Если галочка снята, то компетенция не будет добавлена в карточку.

![](./_images-04/image368.png)

4. **Итог.** Здесь выводится предварительный статус карточки развития, их может быть два: «Карточка развития будет запущена» и «Карточка развития НЕ будет запущена». О причинах блокирующих запуск сказано в колонке «Комментарий».

![](./_images-04/image68.png)

5. **Комментарий.** В этом поле выводится комментарий дополнительная информация о запуске карточек:

- Сколько карточек уже запущено по сотруднику;

- Причины, по которым запуск невозможен.
