## Как это работает

**Получение обновлений**

GitHub Actions проверяет source-репозиторий раз в сутки (или по ручному запуску). При обнаружении новых коммитов анализирует diff каждого коммита. Только файлы в `modules/**/*.md` передаются на обработку. Все запросы к source — read-only через REST API.

**Обработка (AI)**

Каждый изменённый файл передаётся нейросети (`deepseek-v4-flash`) вместе с промптом. Нейросеть анализирует содержимое, определяет принадлежность к одному из 16 модулей, сканирует существующую базу и создаёт либо обновляет инструкцию в формате .md в Obsidian с frontmatter, wikilinks и полной структурой секций.

**Сохранение**

После обработки обновляются служебные файлы (`MOC - Инструкции.md`, `Modules/Module - {Name}.md`) и результат автоматически коммитится в репозиторий базы знаний.

## Запуск

- **Автоматически:** каждый день в 10:00 UTC
- **Вручную:** Actions → Index from Yana → Run workflow

## Структура репозитория

```
qa-knowledge-base-/
├── .github/workflows/index.yml   # Workflow CI
├── fetch.py                      # GitLab API client
├── prompt.txt                    # System prompt для нейросети
├── .yana_last_commit             # Последний обработанный коммит
├── Instructions/                 # 223 инструкции по 16 модулям
├── Modules/                      # 16 файлов модулей
├── MOC - Инструкции.md           # Оглавление
└── MOC - Модули.md               # Оглавление модулей
```

## Технологии

- **Obsidian** — формат базы знаний (markdown + wikilinks + frontmatter)
- **GitHub Actions** — CI/CD платформа, запуск по расписанию
- **GitLab REST API** — получение изменений из source-репозитория
- **OpenCode CLI** — клиент для работы с AI-моделью
- **DeepSeek v4 Flash** — нейросеть для анализа и структурирования контента
- **Python 3** — скрипт интеграции с GitLab API
